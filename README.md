# koetomoProject

koetomo.fun（KoeTomo／声とも）の非公式クライアント／拡張機能をまとめたプロジェクトです。
2つの独立した成果物が入っています。

| プロジェクト | 内容 |
|---|---|
| [`koetomo_qt.zip`](koetomo_qt.zip) | デスクトップクライアント本体（Python + PySide6）。ルーム一覧・タイムライン・プロフィール・DM・検索・フレンド・お知らせを備えたネイティブアプリ |
| [`koetomo_theme.zip`](koetomo_theme.zip) | Chrome拡張機能。koetomo.funのダークモード化＋グループ通話中の音量調整・しゃべり検知・入退室ログ表示 |

両方とも**非公式**です。KoeTomo運営とは一切関係ありません。API仕様の変更で
動かなくなる可能性があります。

# koetomo_qt（デスクトップクライアント）

**ブラウザエンジン(Chromium/WebView)を一切使わない、ネイティブ描画のデスクトップアプリ**です。

## Python 3.12を推奨

Python 3.14環境で複数のネイティブクラッシュ（`Windows fatal exception`）が確認された
ため、**Python 3.12**の使用を強く推奨します。

## セットアップ

`koetomo_qt.zip` を展開し、そのフォルダで:

```bash
py -3.12 -m pip install -r requirements.txt
py -3.12 token_fetcher.py   # 初回のみ: ブラウザでログイン→config.jsonに保存
py -3.12 qt_app.py
```

## ブラウザについて

グループ通話・投稿ボタンは、**声ともがログインを同時に1ブラウザでしか維持できない**ため、
`token_fetcher.py`でログインしたのと同じ**専用のChromeプロファイル**を自動的に使って開きます
（普段使いのデフォルトプロファイルだと、既にChromeが起動していると失敗するため）。
別のブラウザを使いたい場合は、アプリ内の設定(⚙)から実行ファイルのパスを指定できます。

## .exe化する

展開したフォルダで `build_exe.bat` をダブルクリックしてください（内部で`py -3.12`を
使用。Python 3.12が無ければエラーで止まり、インストールを促します）。`dist`フォルダに
`koetomo_client.exe`と`token_fetcher.exe`ができるので、同じフォルダにコピーし、
`config.example.json`も一緒に置いてください（自動コピーはされません）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `qt_app.py` | アプリ本体。PySide6によるGUI一式（ルーム一覧・タイムライン・プロフィール・DM・検索・フレンド・お知らせ・設定） |
| `api.py` | koetomo.funの非公開APIへの薄いラッパー。GUI要素は一切含まない、純粋な通信ロジック |
| `token_fetcher.py` | 初回ログイン用の別プロセス。Chromeを起動し、DevTools Protocol経由でログイントークンを検出して`config.json`に保存する |
| `style.qss` | 見た目の定義（Qt Style Sheet）。Discord風の配色・角丸・ホバー効果 |
| `requirements.txt` | 依存パッケージ一覧（`requests`, `websocket-client`, `PySide6`） |
| `config.example.json` | 設定ファイルのひな形。`token_fetcher.py`実行後、実際の`config.json`が自動生成される（Gitには含めないこと） |
| `build_exe.bat` | Python 3.12を使って`.exe`をビルドするスクリプト |
| `.gitignore` | `config.json`等、ローカル環境固有・機密情報を含むファイルを除外 |

## 開発者向け: スレッド周りの重要な設計判断

通信を伴う処理はすべて素のPython `threading.Thread`で行っています（`QThreadPool`/
`QRunnable`は意図的に不使用）。開発初期に`QThreadPool`のワーカースレッド上で`requests`
や`logging`など無関係な標準ライブラリの内部でネイティブクラッシュが繰り返し発生する
ことが実機の`crash.log`から確認できたため、原因を`QThreadPool`のスレッド生成そのもの
と判断し、素の`threading.Thread`に置き換えています。

その他の設計判断（通信の直列化ロック、`trust_env=False`によるレジストリアクセス回避、
レイアウトクリア時の再帰処理等）は `qt_app.py` / `api.py` 内のコメントを参照してください。

# koetomo_theme（Chrome拡張機能）

koetomo.fun の見た目をダークモード化し、グループ通話中は音量調整・ミュート・
しゃべり検知・入退室ログを表示するChrome拡張機能です。

[koetomo_qt](#koetomo_qtデスクトップクライアント)と組み合わせて使うと、通話をそちら
から開いた場合でもこの拡張機能がそのまま効きます（実際には本物のChromeで開かれるため）。

## できること

- ダークモード（背景色・アクセントカラーのカスタマイズ）
- 自分のマイク音量メーター・ミュート/ミュート解除
- 参加者ごとの個別音量調整＋声とも全体のマスター音量調整（このタブの音声のみ）
- しゃべった時に光るアニメーション（音量をリアルタイム解析）
- 入退室ログ（入室/退室ごとの色分け表示、個別削除・全削除対応）
- 通話履歴（端末ローカルに保存、いつでも削除可能）

**注意**: これは**ブラウザのタブ内**で完結する機能です。Discordのゲームオーバーレイの
ように、ブラウザの外の他アプリ・ゲーム画面に重ねて表示することはできません
（ブラウザ拡張機能の権限では技術的に不可能なため）。

## インストール方法

`koetomo_theme.zip` を展開してから:

1. `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をON
3. 「パッケージ化されていない拡張機能を読み込む」→展開したフォルダを選択

## 使い方

### 基本のダークモード

1. ブラウザ右上の拡張機能アイコン（パズルのピース）から本拡張機能を開く
2. ポップアップ内で「有効にする」をON
3. プリセットカラーから選ぶか、カスタムカラーで好きな色を指定
4. koetomo.fun のページを開く（既に開いていればリロード）と反映される

### 通話中パネル

`koetomo.fun/talk-rooms/...` （グループ通話のページ）を開くと、自動でパネルが
右上に表示されます。

- 「自分のマイク音量」バー: 実際にマイクに向かって喋ると動きます
- 「ミュートにする」ボタン: 実際にマイクをミュート/ミュート解除します
- 「声とも全体の音量」: このタブで聞こえる声とも全体の音量調整（PC全体には影響しません）
- 「参加者」欄: 発言すると緑色に光ります。個別に音量スライダーで調整できます
- 「入退室ログ」: 誰が何分何秒に入室/退室したかを色分けして記録します

### 通話履歴

画面右上の常時表示される⚙アイコン（ドラッグで移動可能）をクリックすると、過去の
通話履歴を確認・削除できます。

## 参加者IDの解決について

音声要素だけでは「誰が」話しているか分からないため、実サイトが参加者情報取得のために
発行する `fetch("/api/users?ids[]=...")` を横取りして対応付けています。この通信が
発生するタイミング次第では、一時的に「ID不明#1」のような表示になり、情報が届き次第
自動的に書き換わります。100%の精度を保証するものではありません。

## 開発者向け

- `mic_hook.js` は `MAIN` world（ページ本体のJS実行コンテキスト）で動作し、
  `getUserMedia`と`fetch`をラップしています。`call_overlay.js`（`ISOLATED` world）とは
  `window`への`CustomEvent`でやり取りしていますが、detailに複雑なオブジェクトを直接
  渡すとworld間でうまく届かないことがあるため、必ずJSON文字列化して渡しています
- サイトのDOM構造（クラス名など）はビルドごとにハッシュ化されて変わるため、
  一部ロジックはあえてDOM構造に依存しない実装（audio要素の存在・fetch横取りのみ）に
  してあります
- 通信は一切行わず、すべてローカル（chrome.storage）で完結します
